## 3. 最高优先级优化

### 3.1 给校验脚本增加“前端脚本语法检查”

原因：

之前页面空白、左侧点击无效，不是数据坏了，而是 HTML 内部脚本多了一个括号，浏览器脚本中断。现有 `validate-brandpulse.ps1` 能检查 JSON 和更新时间，但不能发现这种前端脚本语法错误。

建议：

在最终校验里增加一项：检查 `index.html` 和 `brand-pulse-vis.html` 里的所有 `<script>` 是否能被 Node 解析。

验收标准：

- 如果 HTML 里多一个括号，校验必须失败。
- 如果点击函数、初始化函数所在脚本有语法错误，校验必须失败。
- 校验通过后，再允许打开页面或提交。

### 3.2 重构 HTML 内嵌数据同步方式

原因：

现在 `sync-last-updated.js` 会把 `brands.json` 和 `products/recent.json` 写进 HTML。这个方向是对的，因为 ROBIN 要直接收藏本地 HTML。但当前实现靠正则替换大段 HTML，比较脆弱，之前已经出现过多余括号残留，导致页面交互失效。

建议：

把 HTML 里的内嵌数据区域改成清晰的标记区，例如：

- 品牌数据开始标记
- 品牌数据结束标记
- 产品数据开始标记
- 产品数据结束标记

同步脚本只替换标记区中间的内容，不要用模糊正则扫整段页面。

验收标准：

- 连续运行同步脚本 3 次，HTML 不应产生多余差异。
- 同步后 `index.html` 本地直接打开能显示卡片。
- 同步后 `brand-pulse-vis.html` 也不能出现脚本语法错误。

### 3.3 修复同步脚本里的中文乱码输出

原因：

当前 `sync-last-updated.js` 里有一处日志文本已经乱码。虽然不一定影响页面功能，但这是编码链路不稳定的信号。

建议：

把脚本内部日志统一改成 ASCII 或稳定英文，例如 `Using embedded product data`。页面给用户看的中文不受影响，脚本日志不要放中文。

验收标准：

- 同步脚本里不再出现乱码文本。
- PowerShell、Node、Git diff 中都不出现异常乱码。

## 5. 页面体验优化

### 5.1 首屏状态要真实，不要静态写死数字

原因：

之前截图里左侧显示 `6`，但实际应显示 `24` 条精选。这类数字如果写死，会让用户误判自动化是否正常。

建议：

HTML 初始数字可以写 `0` 或 `加载中`，页面初始化后由脚本统一刷新。

验收标准：

- 页面刚打开时不显示误导性的旧数字。
- 脚本运行后，左侧、底部统计、列表数量一致。

### 5.2 点击无效要有自动发现机制

建议：

在校验里增加最小交互检查：

- 页面脚本能解析。
- 存在 `switchSection`。
- 存在 `initializeDashboard`。
- 初始化后理论上至少能筛出 1 条精选，除非当天是 no-signal。

验收标准：

- 如果页面函数缺失，校验失败。
- 如果数据里有精选但页面逻辑筛不出来，校验失败。

## 6. 自动化链路优化

### 6.1 每日自动化结果要输出“人能看懂的摘要”

当前脚本会输出一些 JSON 和完成信息，但 ROBIN 更需要直接知道：

- 今天新增了几条。
- 今天有没有高价值信号。
- 今日更新为什么为空或不为空。
- 是否打开了日报页。
- 是否存在需要人工确认的问题。

建议：

每日 pipeline 最后生成一个简短摘要文件，例如：

`data/daily-run-summary-YYYY-MM-DD.md`

注意：这个摘要文件默认留本地，不提交公开仓库。

验收标准：

- TRAE 执行后能直接把摘要读给 ROBIN。
- 摘要里不要堆原始 JSON。

### 6.2 区分“本地收藏版”和“公开网站版”

当前项目同时承担两种用途：

- 本地收藏版：HTML 内嵌数据，直接打开即可。
- 公开网站版：HTML 加公开 JSON，部署到 GitHub Pages 等。

这两种模式不要混在一起判断。

建议：

在交付说明里明确：

- ROBIN 日常看本地收藏版。
- GitHub 公开仓库只提交展示层和允许公开的数据。
- 私有脚本、R1、候选池、判断标准不提交公开仓库。
