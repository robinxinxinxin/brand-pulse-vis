## 2. 还存在的优化空间

### 2.1 校验脚本里的“精选数量”口径和页面不一致

当前发现：

- 页面精选口径：`score >= 75` 或 `visTotal >= 7`
- 校验脚本精选口径：`score >= 70` 且 `reviewStatus = verified`

所以会出现：

- 页面实际精选：24
- 校验脚本报告精选：25

这不是功能错误，但会影响验收汇报。ROBIN 看到两个数字不一致，会怀疑自动化又坏了。

建议：

把校验脚本里的精选口径改成和页面完全一致。

验收标准：

- 校验输出的 featured 数量和页面左侧“精选”数量一致。
- 当前应统一为 24，除非产品数据发生变化。

### 2.2 `validate-brandpulse.ps1` 依赖系统里的 `node`

当前校验脚本用的是 `node --check`。

风险：

如果 TRAE 或另一台机器的 PATH 里没有 Node，校验会失败；但项目其实有 Codex bundled Node 路径可用。

建议：

给校验脚本增加 Node 查找策略：

1. 先用 PATH 里的 `node`。
2. 如果没有，再尝试常见 Codex runtime Node。
3. 如果仍没有，给出清楚错误：“缺 Node，无法做前端脚本语法检查”。

验收标准：

- 没有 Node 时，不要报一堆难懂错误。
- 有 Node 时，继续做 HTML 脚本语法检查。

### 2.3 校验脚本只做语法检查，还没有做“首屏可渲染”逻辑检查

当前已经能发现多余括号这类语法错误，这是进步。

但还不能发现这些问题：

- 数据有 24 条精选，但页面筛选逻辑算出来是 0。
- 品牌池没内嵌成功，导致产品被监控品牌过滤掉。
- `initializeDashboard` 存在，但初始化后不会真正渲染。

建议：

在校验里增加一个轻量逻辑检查，不需要真的打开浏览器：

- 读取 `brands.json`
- 读取 `products/recent.json`
- 按页面同样规则计算“可见产品数”和“精选数”
- 如果产品不是 no-signal，但可见精选为 0，就失败

验收标准：

- 当前应算出：可见产品约 26，精选约 24。
- 如果品牌池或产品池断了，校验失败。

### 2.4 `AGENTS.md` 已经过时

当前 `AGENTS.md` 仍然描述很多人工搜索、手工更新 HTML 的流程。

但现在项目已经变成：

- 脚本生成关键词
- 候选池可选输入
- 规则评分
- 去重
- 归档
- 同步 HTML 内嵌数据
- 校验
- 自动打开本地页

风险：

TRAE 如果只读 `AGENTS.md`，可能按旧流程手工改 HTML，反而绕过新自动化。

建议：

更新 `AGENTS.md`，把它改成当前真实流程。旧的人工步骤可以保留为“兜底方式”，但不要放在主流程。

验收标准：

- TRAE 读完 `AGENTS.md` 后，会优先运行 `scripts/run-daily-pipeline.js`。
- 不会再手工往 `index.html` 里粘大段产品数据。
- 明确说明 `scripts/` 是私有自动化核心，不提交公开仓库。

### 2.6 `data/` 下交接文件在 PowerShell 里可能显示乱码

复查时发现，用 PowerShell 直接读取中文 Markdown 时可能显示乱码。

这不一定是文件坏了，通常是终端编码问题。但对 TRAE 交接来说，容易误判。

建议：

TRAE 读取交接文件时，应使用 UTF-8 方式读取，或直接在编辑器里打开。

如果要进一步稳妥，可以额外生成一份 ASCII 文件名、UTF-8 BOM 的交接副本，避免老 PowerShell 显示异常。

验收标准：

- TRAE 能正常读懂中文交接内容。
- 不因为终端乱码误以为文件损坏。
